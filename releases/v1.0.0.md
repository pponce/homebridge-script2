# Script2 1.0.0

# ⚠️ **BREAKING CHANGE — BACK UP YOUR CONFIGURATION BEFORE UPDATING.**

**Version 1.0.0 removes legacy Script2 accessory mode and old platform configuration formats. Review and save a copy of your current Homebridge config.json before installing, then follow the [migration guide](https://github.com/pponce/homebridge-script2/blob/master/MIGRATION.md). Legacy configurations will no longer run.**

**Already using Script2Platform with on_off_switches and stateless_switches? No list-format migration is needed. Your entries must pass the new validation; keep accessory names unchanged.**

**Stable release:** 1.0.0 is published on the `latest` channel following 1.0.0-beta.1. Requires Node.js 22.13+ within Node 22, or Node 24, and Homebridge 1.8+ within version 1, or version 2.

**Already on 1.0.0-beta.1?** No additional configuration migration is required. This release promotes the beta implementation to stable and updates release documentation and publishing metadata.

## Before you update

1. Download a Homebridge backup and save your full config.json separately. Record rooms, scenes, and automations that use Script2.
2. Check for old standalone `accessories` entries using `"accessory": "Script2"`, or platform keys `devices`, `stateful_devices`, `stateless_devices`, `On/Off Switches`, or `Stateless Switches`.
3. Move old entries into `on_off_switches` or `stateless_switches`. Use an explicit `trigger` command for stateless switches and remove `device_type`. The current 0.4.6 release already supports the two current lists, so you can migrate and test before installing 1.0.0.
4. Keep exact accessory names. Moving from standalone accessory mode may create new HomeKit accessories and require repairing rooms, scenes, and automations. Do not delete the entire Homebridge accessory cache.

## New settings experience

- Named switch cards, clear Add buttons, conditional state-source controls, and collapsible advanced settings.
- Polling, state caching, output matching, exit-code policy, serial numbers, and timing settings are available in the custom editor.
- Timings display in seconds; existing JSON values remain in milliseconds.
- Inline validation and synchronized saving protect against incomplete configuration and rapid-edit races.
- Opening or saving settings never executes a script.

## Reliability fixes

- Configuration is validated before commands, watchers, or polling start. Invalid configuration does not wipe cached accessories.
- File-state notifications update HomeKit without re-running ON/OFF commands. Flags that are absent at startup are detected when created; their parent directory must exist.
- Command launch errors, watcher errors, callback failures, and shutdown are handled. Pending requests finish with an error on shutdown, and late completions cannot start queued commands.
- Concurrent stateless activations share one execution; subsequent intentional activations can run again. A zero reset delay now works.
- Command timeouts, termination, and output overflow fail state reads even if partial output is available. Ordinary nonzero state exits still honor `fail_on_state_exit_code`.
- Successful actions remain visible at info level; routine reads and polling stay at debug level. Raw command strings and output are omitted from plugin diagnostics.

## Preserved behavior

Per-switch ON/OFF serialization, duplicate suppression, shared state reads, cache TTL, stale-read protection, and optional early HomeKit acknowledgement remain supported. `homekit_set_ack_timeout_ms` still defaults to `0` (wait for command completion). Acknowledgement does not prove the external action completed; late failures use the configured state source to reconcile HomeKit.

## Install and test

In Homebridge UI, use the plugin's version selector and choose **1.0.0** / **latest**, then restart the relevant Homebridge instance or child bridge. Confirm ON/OFF actions, state reads, polling or file-state updates, stateless reset, and your scenes/automations. Test your configured scripts under the Homebridge service account without interactive prompts.

To roll back, select **0.4.6** and restore the matching saved configuration. Room/scene assignments may still need repair if accessory identities changed.

This release prepares Script2 for Homebridge verification. It does not mean the plugin has been certified or approved.
