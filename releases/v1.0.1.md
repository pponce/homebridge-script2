# Script2 1.0.1

# ⚠️ **BREAKING CHANGE — BACK UP YOUR CONFIGURATION BEFORE UPDATING.**

**For users upgrading from versions before 1.0.0: legacy Script2 accessory mode and old platform configuration formats are no longer supported. Review and save a copy of your current Homebridge config.json before installing, then follow the [migration guide](https://github.com/pponce/homebridge-script2/blob/master/MIGRATION.md). Legacy configurations will no longer run.**

**Already using 1.0.0 or 1.0.0-beta.1? No configuration changes or additional migration are required for this update.**

## Fixed

- Correct the configuration schema to use a standard object-level `required` array instead of boolean `required` properties on individual fields.
- Keep the platform display name optional, matching the existing runtime validator. Individual switch names and commands remain required.
- Reorganize the README into one quick start, linked sections, a minimal example, a settings reference with timing units, and advanced behavior notes. Preserve the FAQ, top icon, and original-plugin reference at the bottom.
- Validate the schema against JSON Schema rules during development, CI, and release checks. Add regression coverage for the reported error and existing configurations without a platform display name.

This patch changes schema metadata and validation tooling. Script execution, settings, accessory identities, and runtime dependencies are unchanged from 1.0.0. The large migration warning remains in both Release Notes and Changelog for users upgrading from pre-1.0 versions.

## Update

Select **1.0.1** / **latest** in Homebridge UI and restart the instance or child bridge running Script2. Keep your existing valid platform configuration.

Requires Node.js **22.13+ within Node 22, or Node 24**, and Homebridge **1.8+ within version 1, or version 2**.

This release addresses the configuration-schema issue reported during Homebridge review. Verification remains subject to Homebridge team approval.
